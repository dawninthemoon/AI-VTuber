# 음성 입력 처리

마이크 인식은 계속 수행하고, 인식이 끝난 문장을 메모리에 순서대로 보관합니다.
서버 요청 전용 작업자는 한 번에 요청 하나만 보냅니다.

예: A를 전송한 뒤 답변 생성/음성 재생 중 B, C를 말하면, A의 마지막 음성
재생 완료를 확인한 뒤 `B\nC`를 하나의 다음 요청으로 보냅니다.
그 요청 처리 중 들어온 D는 다시 다음 차례로 모읍니다.
기존의 2초 이내 동일 인식 결과 중복 제거는 유지합니다.

특정 단어를 치환하지 않고 모델의 인식 결과를 그대로 서버에 보냅니다.
NVIDIA CUDA GPU와 실행 라이브러리를 사용할 수 있으면 다국어 Whisper `turbo` 모델을
`int8_float16`으로 사용하고, 그렇지 않으면 기존 `small`/CPU/`int8` 설정을
사용합니다. 첫 `turbo` 실행에서는 약 1.6GB의 모델 파일이 다운로드됩니다.
Windows에서는 RealtimeSTT 환경이나 같은 Conda 설치의 `GPTSoVits` 환경에
있는 CUDA DLL을 찾아 사용합니다. 다른 위치에 있다면
`AIVTUBER_STT_CUDA_DLL_DIR`로 해당 폴더를 지정할 수 있습니다.
`AIVTUBER_STT_MODEL`, `AIVTUBER_STT_DEVICE`, `AIVTUBER_STT_COMPUTE_TYPE`
환경 변수로 모델과 실행 장치를 직접 지정할 수 있습니다. 변경 사항은 STT를
다시 시작해야 적용됩니다.

서버는 `/chat` 응답의 `audioVersion`으로 마지막 생성 음성을 알려주고,
Unity는 `/voice/playback`의 `completedVersion`으로 재생 완료를 알립니다.
마지막 음성 완료 및 재생하지 않는 상태가 0.8초 유지되어야 다음 요청을 보냅니다.
음성이 생성되지 않은 응답(`audioVersion: 0`)은 재생 버전 확인을 생략합니다.

## 실행 시 주의

- 서버, Unity, STT를 함께 업데이트하고 Unity를 Play Mode로 실행한 뒤 사용하세요.
- Unity가 연결되지 않거나 마지막 음성 다운로드/재생이 실패하면 입력을 계속 모으며 완료를 기다립니다. 10초마다 대기 안내를 출력합니다.
- 입력을 계속 받으므로 AI 스피커 소리도 인식될 수 있습니다. 헤드폰을 사용하세요. 이 변경에 에코 제거는 포함되지 않습니다.
- 저장은 실행 중 메모리 보관입니다. 종료 시 미전송 문장을 로그에 표시하지만 재시작 후 자동 복구하지 않습니다.
- 요청 실패/타임아웃 시 서버가 이미 처리했을 가능성이 있어 다음 요청과 자동 재전송을 중단합니다. 로그와 서버 상태를 확인하고 STT를 재시작하세요.
- 이 대기열은 해당 STT 프로세스의 입력에 적용됩니다. 웹 UI나 다른 클라이언트에서 동시에 보내는 요청은 같은 대기열에 들어가지 않습니다.

## 검증

마이크와 모델 없이 대기열 병합, 처리/재생 중 요청 차단, 재생 완료 확인 및 요청 실패 처리를 검사합니다.

```bash
python3 -m unittest discover -s Tools/RealtimeSTT -v
```
